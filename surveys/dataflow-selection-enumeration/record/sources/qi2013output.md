# Path Exploration Based on Symbolic Output

## Evidence

### Why it matters

PESO is the closest formal predecessor found for output-directed path
enumeration. It partitions executions by a *relevant-slice condition* (RSC),
proves that one RSC fixes the symbolic values at the requested output, and gives
an exploration algorithm that is complete under explicit assumptions. Broad
claims that output-directed symbolic execution need explore only semantically
relevant branches are therefore established prior art.

### Program and semantic model (RQ1, RQ7)

The paper operates on Java bytecode traces generated by dynamic symbolic
execution. An execution has a path condition, dynamic statement instances, and
symbolic values. A slicing criterion is one or more output statement instances;
the exposition assumes it postdominates method entry, and gives a transformation
for criteria that do not.

The ideal result assumes exact symbolic modeling, a sound and complete SMT
solver, and a bounded number of distinct RSCs. The implementation deliberately
underapproximates some Java features, notably arrays and polymorphism, so its
experimental RSC coverage is not a proof of completeness for full Java.

### Enumerated object (RQ2–RQ3)

The *relevant slice* of an execution is the transitive closure of dynamic data
dependence, dynamic control dependence, and *potential dependence*. Potential
dependence retains a branch whose other outcome could cause a definition to
reach the criterion, even when that definition is absent on the observed trace.
The execution index distinguishes dynamic instances across loops.

The RSC is the conjunction of just those branch conditions whose instances are
in the relevant slice. Branches outside the slice are omitted. Thus the paper
enumerates representatives of RSC classes, not ordinary control-flow paths.
Each reported case pairs an RSC with the symbolic output values observed on its
representative execution.

### Algorithm

Naively applying DART to the shortened RSC is incomplete: removing an earlier
irrelevant predicate can make a later relevant predicate disappear from the
usual prefix-negation search. `RSCExplore` (Algorithm 1) therefore:

1. executes an initial input and computes its RSC;
2. reorders RSC predicates in a quicksort-like dependency order, placing
   predicates needed to reproduce a pivot before the pivot;
3. pushes negations of the resulting prefixes onto a work stack;
4. solves each formula, executes the model, and computes the newly observed
   RSC; and
5. tracks the explored-prefix depth to avoid re-enqueuing duplicate work.

### Guarantees (RQ4)

- Lemma 3.2 states that any input satisfying the RSC for an execution reaches
  the criterion with the same symbolic values, the same relevant slice, and the
  same outcomes at branch instances in that slice.
- Theorem 3.3 concludes that identical RSCs imply identical symbolic values at
  the slicing criterion.
- Theorem 3.14 states that, if the number of RSCs is bounded, every feasible
  trace's RSC is represented by an execution found by `RSCExplore`, regardless
  of the initial test.

These are not a minimality or canonical-quotient result. The implication in
Theorem 3.3 is one-way: conservative slicing or syntactically different RSCs can
distinguish executions with equal outputs. The paper does not state pairwise
disjointness of its presented formulas modulo logical equivalence.

### Residuals, witnesses, and sharing (RQ5)

The solver models are concrete test inputs and therefore witnesses. Each RSC is
associated with symbolic output values, which play the role of residuals. The
paper does not expose a reusable residual dataflow graph, explicit graph
sharing, or compositional subgraph summaries.

### Complexity and performance (RQ6)

The number of RSCs remains exponential in the number of relevant branches in
the worst case. No output-sensitive theorem or `K+1`-query bound is given.
Empirically, PESO generated fewer tests and solver calls than conventional DSE:
for example, Schedule used 3 rather than 75 tests and 13 rather than 932 solver
calls; Tcas used 29 rather than 88 tests. Reported RSC coverage is lower on some
subjects because of implementation underapproximation (for example, 75% on BST
and 79% on OrdSet).

### Motivating example (RQ8)

The running `foo(x,y,z)` example has eight control-flow paths but three
output-relevant cases:

- `x-y > 0 && x+y > 10`, returning `x`;
- `x-y <= 0 && x+y > 10`, returning `y`; and
- `x+y <= 10`, returning constant `2`.

A branch on `z*z` affects only printing, so it is absent when the return value
is the slicing criterion. This is a strong precedent for our motivating
example; any reuse should cite PESO and make the dataflow-specific distinction
explicit.

## Bearing on RQs

What is directly established by the work: output-directed path quotienting by
relevant branch instances, guarded symbolic outputs, witnesses, and complete
discovery of all RSCs under the paper's boundedness and solver assumptions.

Our interpretation or inference: translating a finite pure selection DAG to
control flow and choosing its result as the slicing criterion makes an RSC
look very much like a selection observation. The remaining distinctions are
that our proposed object is an explicit partial map from contextual selection
sites to outcomes, its domain is defined by selected-edge demand rather than
dynamic potential-dependence slicing, and its records are intended to be exact
input fibers with shared residual DAGs and compositional summaries.

Could it subsume our proposed contribution: it subsumes the broad thesis that
output-relevant path classes can be explored without enumerating all paths. It
may also subsume a non-compositional control-flow encoding of finite selection
observations. A defensible original contribution must prove a sharper
relation: for example, exact fiber and uniqueness properties of the
structural observation, an output-sensitive algorithm with a precise query
bound, or compositional summaries that PESO does not provide.

## Evidence limits

- Are selection-observation fibers strictly finer or coarser than ideal RSC
  classes on a pure acyclic translation, or are they isomorphic?
- Can conservative potential dependence retain a selection site that
  selected-edge demand would prove irrelevant?
- Does explicit contextual site identity yield a canonical partition where RSC
  syntax does not?
